🔴 Bugs Críticos (2)
🔴 Crítico
Anexo III usa alíquotas nominais, não efetivas
Linhas 881–888 (array) e 919–927 (modal) Bug documentado — confirmado LC 123/2006, Anexo III

O array ANEXO_III armazena a alíquota nominal bruta do Simples Nacional (ex: das: 33.00 para a faixa 6). A alíquota exibida no modal e aplicada ao cálculo está incorreta para as faixas 3 a 6. A lei exige a fórmula de alíquota efetiva:

// Correto — LC 123/2006, Anexo III
aliqEfetiva = (RBT12 × aliqNominal − PD) / RBT12

// Exemplo: faixa 6 com RBT12 = R$ 4.200.000
// nominal: 33%  |  PD: 648.000
efetiva = (4.200.000 × 0,33 − 648.000) / 4.200.000
efetiva = 17,57%  ← o simulador exibe 33% — erro de 15pp

O erro se propaga diretamente para o cálculo de baseSemIVA e precoFuturo quando o usuário usa o botão "Aplicar" do modal. Para a faixa 6, o preço futuro fica superestimado em proporção ao erro de 15 pontos percentuais.

Ação: Adicionar coluna pd (parcela a deduzir) ao array ANEXO_III e recalcular as colunas consumo e renda com a fórmula efetiva. Alternativamente, exibir a tabela apenas como referência nominal e orientar o usuário a inserir a alíquota efetiva calculada pelo PGDAS-D.
🔴 Crítico
Cronograma de transição ausente — CBS 2027 vs. IBS 2028–2032
Linhas 1068–1083 (calcular) Novo achado EC 132/2023 · LC 214/2025

O simulador trata o cenário futuro como "regime pleno de 2033" em todos os cálculos, aplicando sempre aliqCBS + aliqIBS como se ambos estivessem em vigor simultaneamente. O consultor fiscal externo apontou esta omissão como impacto relevante para a ferramenta comercial.

O cronograma legal é:

  • 2026: Teste CBS/IBS a alíquotas reduzidas (0,1%)
  • 2027: CBS pleno (substitui PIS/COFINS); IBS ainda inexistente
  • 2028–2032: IBS escalonado (1/6 por ano a partir de 2029); ICMS/ISS reduzidos proporcionalmente
  • 2033: IBS pleno; extinção definitiva de ICMS e ISS

Consequência: para simulações de 2027 (CBS em vigor, sem IBS), a carga tributária futura está superestimada em 17,7 pontos percentuais. Clientes podem não precisar reajustar preços em 2027 se o consultor não souber desta distinção.

Ação sugerida: Adicionar seletor "Ano de referência" (2027, 2028–2030, 2031–2032, 2033) e aplicar fatores de escalonamento ao IBS. No mínimo, adicionar disclaimer textual explicando que o simulador projeta o regime pleno de 2033.
🟠 Inconsistências Altas (3)
🟠 Alto
warningPresumido com condição incompleta
Linha 1004 Bug documentado — confirmado

O aviso sobre o regime Presumido (PIS/COFINS cumulativo, sem transferência de crédito) dispara somente quando regimeCliente === 'real_com_credito'. O correto é disparar para qualquer combinação de cliente, já que nenhum cliente toma crédito de PIS/COFINS quando a locadora é Presumida — independentemente do regime do cliente.

// Código atual — incorreto
if (regimeLocadora === 'presumido' && regimeCliente === 'real_com_credito') {
    warnPresumido.classList.add('active');
}

// Correto
if (regimeLocadora === 'presumido') {
    warnPresumido.classList.add('active');
} else {
    warnPresumido.classList.remove('active');
}

Impacto: usuário Presumido com cliente real_sem_credito, presumido ou simples_nc não recebe o aviso e pode interpretar incorretamente o campo "Custo final do cliente".

Ação: Alterar a condição do if para verificar apenas regimeLocadora === 'presumido', sem a restrição ao regime do cliente.
🟠 Alto
Simples Simplificado aplica alíquotas plenas CBS/IBS
Linha 1048 Bug documentado — confirmado LC 214/2025, art. 16

Os branches simplificado e nao_cumulativo aplicam exatamente as mesmas alíquotas (cbsEst e ibsEst). A LC 214/2025 prevê alíquotas reduzidas específicas para o Simples Simplificado — ainda pendentes de regulamentação pelo Comitê Gestor do IBS.

O simulador sobreestima sistematicamente a carga do Simplificado. Não há nota ao usuário sobre essa incerteza regulatória.

Ação: Manter as alíquotas plenas como proxy enquanto a regulamentação não sai, mas adicionar disclaimer explícito: "Alíquotas reduzidas do Simples Simplificado pendentes de regulamentação pelo Comitê Gestor. Valores estimados com alíquotas plenas."
🟠 Alto
Crédito presumido do Simples Simplificado (cliente) ignorado sem aviso
Linha 1087 Novo achado LC 214/2025

O array regimesQueTomamCredito não inclui simples_sim, portanto valorCreditoFuturo = 0 para clientes Simples Simplificado. A LC 214/2025 prevê crédito presumido para esse regime (percentual ainda pendente de regulamentação).

// Atual — simples_sim excluído
const regimesQueTomamCredito = [
    'real_com_credito', 'real_sem_credito',
    'presumido', 'simples_nc'
    // 'simples_sim' ausente — crédito presumido não computado
];

O usuário pode interpretar que "Simples Simplificado não tem crédito futuro", o que é incorreto. A omissão é conservadora (superestima o custo), mas induz a erro de percepção sobre a reforma.

Ação: Incluir simples_sim com crédito presumido parametrizável (valor zero até regulamentação) ou adicionar um disclaimer específico no boxAnalysis para este cenário explicando que o crédito existe mas aguarda regulamentação.
🟡 Fragilidades Médias (3)
🟡 Médio
Label "com crédito" estático exibido mesmo sem crédito
Linha 791 (HTML) Novo achado

O rótulo "Custo final do cliente (com crédito)" é estático no HTML. Quando a locadora é Presumida ou Simples (ou quando o cliente não toma crédito), o valor em resCustoRealAtual é igual ao preço bruto (crédito = zero). O label "com crédito" induz interpretação incorreta sobre a existência de créditos.

Ação: Tornar o label dinâmico via JS: alternar entre "Custo final do cliente (sem crédito PIS/COFINS)" e "Custo final do cliente (descontado crédito PIS/COFINS)" conforme creditoPisCofinsHoje > 0.
🟡 Médio
ID rowRefImposto definido no HTML, nunca referenciado no JS
Linha 821 (HTML) Novo achado

O elemento id="rowRefImposto" existe no HTML mas nenhum getElementById('rowRefImposto') aparece no JavaScript. É funcionalmente correto por acidente (o elemento nunca precisa ser ocultado hoje), mas o ID morto cria risco de manutenção: qualquer desenvolvedor que precise controlar a visibilidade dessa linha não encontrará o padrão esperado.

Ação: Remover o ID do HTML ou adicionar o getElementById correspondente no JS para consistência com o padrão do arquivo.
🟡 Médio
Inputs extremos causam falhas silenciosas
Linhas 1064 e 1073 Novo achado

Cenário 1: aliqSimplesRenda ≥ 100% — a guarda aliqRendaFrac < 1 evita divisão por zero, mas o fallback retorna receitaLiquida diretamente, ignorando a parcela renda. Resultado parece válido mas está incorreto, sem mensagem de erro.

Cenário 2: soma das alíquotas atuais > 100% (ex: PIS 60% + ICMS 50%) — receitaLiquida fica negativa. O precoFuturo também fica negativo e é exibido como "R$ -X.XXX,XX" sem alerta ao usuário. Os campos têm min="0" por campo, mas não há validação da soma total.

Ação: Adicionar validação da soma total das alíquotas. Se aliqTotal ≥ 100, exibir aviso e suprimir os resultados. Para aliqSimplesRenda ≥ 100, tratar como erro de input explícito.
✅ Aspectos Verificados e Corretos (5)
✅ Correto
Invariante de receita líquida preservada em todos os regimes
Linhas 1064, 1077, 1083

receitaLiquida = precoAtual − impostoAtualValor é calculada corretamente. O precoFuturo é derivado desta base em todos os branches (Presumido, Real, Simples). Não há cálculo isolado do preço futuro sem respeitar a invariante. Validado pelo consultor fiscal externo.

✅ Correto
IVA "por fora" aplicado corretamente
Linhas 1077 e 1083

Em ambos os branches, o IVA é somado à base (precoFuturo = baseSemIVA + valorIVA), não embutido como os tributos atuais. Implementação correta da metodologia "por fora" da LC 214/2025.

✅ Correto
Crédito PIS/COFINS hoje: somente Lucro Real + Lucro Real
Linha 1031

Crédito PIS/COFINS hoje existe apenas quando locadora=Real E cliente=real_com_credito. Presumido usa regime cumulativo (Lei 9.718/98, art. 8º) — sem crédito. Simples também sem crédito. Implementação correta.

✅ Correto
Crédito IVA futuro: Presumido e Real sem crédito incluídos
Linha 1087

regimesQueTomamCredito inclui corretamente real_sem_credito e presumido. Isso reflete a eliminação da distinção insumo/consumo pela LC 214/2025 — todos os regimes passam a ter direito a crédito de IVA na reforma.

✅ Correto
Separação renda/consumo no Simples Nacional
Linhas 1068–1077

A parcela de renda (IRPJ/CSLL/CPP) permanece no DAS pós-reforma. A fórmula baseSemIVA = receitaLiquida / (1 − aliqRendaFrac) está matematicamente correta para isolar a base tributável pelo IVA. Validado pelo consultor fiscal externo.

💼 Feedback do Consultor Fiscal Externo

Contexto

O simulador foi avaliado por um consultor fiscal externo especializado em reforma tributária. O consultor confirmou que os cálculos estão matematicamente corretos ("por dentro") em todos os cenários. Os pontos abaixo são observações sobre contextualização, completude e oportunidades de diferenciação comercial da ferramenta.

📌 Ponto 1 — Cronograma de transição CBS vs. IBS Ausente no simulador

CBS entra em 2027 (substitui PIS/COFINS integralmente). IBS entra gradualmente entre 2028 e 2032 (extinção de ICMS/ISS apenas em 2033). O simulador atual não distingue os anos de transição — projeta sempre o regime pleno de 2033. Clientes da locadora podem não precisar de reajuste em 2027 se o IBS ainda não estiver vigente. A ausência desta contextualização pode gerar expectativas erradas nas negociações comerciais.

📌 Ponto 2 — IVA Dual: CBS+IBS aplicados conjuntamente a partir de 2028 Parcialmente tratado

Na metodologia do IVA Dual, CBS e IBS são aplicados em conjunto. O aumento real de carga tributária começa em 2028, quando o IBS entra em escalonamento. O simulador calcula a carga conjunta corretamente para o regime pleno, mas não oferece visão do impacto por ano de transição.

📌 Ponto 3 — Impacto diferencial por regime: Presumido e Simples são os mais beneficiados Calculado, mas não comunicado

Lucro Real é o menos impactado: já possui créditos de PIS/COFINS hoje. A cadeia de creditamento do IVA muda a estrutura, mas o impacto líquido é menor.

Lucro Presumido e Simples Nacional atualmente não têm créditos de PIS/COFINS (regime cumulativo / regime Simples). Isso cria uma distância maior entre o cenário atual e o novo — e essa distância é positiva para os clientes desses regimes, pois passam a ter acesso a crédito de IVA que antes não existia. Este é um argumento comercial relevante que o simulador calcula numericamente, mas não contextualiza de forma didática para o usuário.

Recomendações derivadas do feedback

  • Adicionar seletor de ano de referência (pelo menos 2027 vs. 2033) para contextualizar o cronograma da reforma.
  • No boxAnalysis, incluir contextualização textual sobre por que o custo caiu ou subiu — especialmente para Presumido e Simples, onde a eliminação da cumulatividade é o fator central.
  • Adicionar seção educativa explicando que Lucro Real já tem créditos hoje (menor impacto) e que Presumido/Simples ganham créditos que não tinham (maior benefício relativo).
